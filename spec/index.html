    Functional Description

    Purpose

    This IP provides a fully synthesizable RTL implementation of a HyperBus Controller, enabling seamless communication between an on-chip system and off-chip HyperBus devices such as HyperRAM and HyperFlash memories. It abstracts the complexity of the HyperBus protocol and exposes a standard AXI4 interface to system controller.

    Usage context

    HyperBus is primarily used for connecting high-bandwidth, low-pin-count external memories such as HyperRAM (PSRAM) and HyperFlash (NOR Flash). The controller can also interface with generic peripherals that implement the HyperBus electrical and timing specifications.

    Typical applications include:

    • MCU/SoC memory expansion
    • Low-latency code-execution interfaces (XIP) from HyperFlash
    • Framebuffer or scratchpad memory using HyperRAM
    • FPGA-based embedded systems requiring compact, high-speed external memory

    Supported standards/protocols

    This peripheral implements:

    • AXI4 slave interface (read/write channels, bursts, protection attributes)
    • HyperBus protocol as defined in the publicly available specification (Cypress/Infineon HyperBus Specification, v1.x)
    • Standard signaling for HyperRAM and HyperFlash devices, including:
      • CK/CK#, RWDS, CS#, and bidirectional DQ[7:0]
      • Row/column addressing for HyperRAM
      • Command/address packet formats for HyperFlash

    The address width is also fully parameterizable. We support bursts of any size permitted by AXI and stalling through PHY-level clock stopping and protocol-level burst splitting. We do not buffer bursts to support devices without the clock stop feature; please ensure your device supports clock stop or ensure sufficient buffering upstream.

    The configuration register interface uses the minimal Regbus protocol. Data and address widths are parameterizable, but register sizes must be a power of two larger than 16 bits.

    Interface

    Register Map

    Register set for runtime configuration:

    • Latency mode selection
    • Burst configuration
    • Device timing parameters (tACC, tRC, tCSHI, etc.)
    • Refresh optimization (for HyperRAM)
    • Status registers for monitoring state, errors, and device behavior
    • Power management
    • Support for HyperRAM low-power modes (Hybrid Sleep/Deep Power-Down)
    • Clock gating and internal low-activity states
    • Optional features (depending on specific implementation variants)
    • Error detection (timeouts, protocol violations)
    • ECC pass-through or simple parity support
    • Multi-chip mode (multiple CS# lines)
    • XIP-friendly read pipeline for HyperFlash

    Features/Requirements

    The HyperBus Controller bridges AXI4 transactions to HyperBus read/write operations. Its main architectural features include:

    • Command & transaction management
    • Automatic generation of HyperBus command/address packets
    • Support for both memory types:
      • HyperRAM: variable-latency reads, fixed-latency writes
      • HyperFlash: command sequences, linear reads, programming operations
    • Burst assembly and splitting based on AXI burst structure and device constraints
    • Timing control
    • CK/CK# differential clock generation
    • RWDS monitoring for read latency determination and data strobe alignment
    • Turnaround, idle cycles, and write-to-read or read-to-write transitions
    • Optional internal timing calibration (if enabled in the integration)
    • AXI interface handling
    • AXI4-compliant read/write slave interface
    • Burst length translation, alignment correction, and response generation
    • Back-pressure and outstanding transaction control
    • Independent read and write paths

    The main restrictions are as follows:

    • Atomics are not supported.
    • Only linear bursts are supported.
    • All accesses except byte-size accesses must be aligned to 16-bit boundaries.
    • Only communication with HyperRAMs has been tested. Support for flash is WIP.
